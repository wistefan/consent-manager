## Description

Implement the PostgreSQL schema, the Java domain entities, and the Micronaut Data JDBC repositories
for the four remaining aggregates: **User**, **Participant**, **PrivacyNotice**, and **Consent**
(with its event log).

The `UserIdentifier` entity is **not** part of this design. It has been replaced by a
`user_participants` link table — see Section "Replacing UserIdentifier" below.

## Technical Details

### Design Rules

1. **Primary keys are UUIDs**, generated by the application (UUIDv7 preferred for index locality).
   They are internal.
2. **`users.identifier` and `participants.identifier` are the natural keys** and carry unique
   constraints. External APIs address entities by these global identifiers, not by UUID.
3. **Enums are stored as `text` with a `CHECK` constraint**, not as PostgreSQL `ENUM` types —
   adding a state must be a one-line migration, not a type alteration.
4. **Contract-derived, non-queried structures are `jsonb`**; anything filtered, joined or sorted on
   gets a real column.
5. **Every foreign key declares an explicit `ON DELETE` policy.** The original implementation had no
   cascade behaviour at all (original bug 05-PM-12.6); making it explicit in DDL closes that gap by
   construction.
6. **No `schema_version` column** — Flyway owns schema versioning.

### Schema (`db/migration/V1__initial_schema.sql`)

```sql
CREATE TABLE users (
    id              uuid PRIMARY KEY,
    identifier      text NOT NULL,
    email           text,
    first_name      text,
    last_name       text,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT users_identifier_key UNIQUE (identifier)
);
CREATE INDEX users_email_idx ON users (lower(email)) WHERE email IS NOT NULL;

CREATE TABLE participants (
    id                    uuid PRIMARY KEY,
    identifier            text NOT NULL,
    legal_name            text NOT NULL,
    self_description_uri  text,
    email                 text,
    endpoints             jsonb NOT NULL DEFAULT '{}'::jsonb,
    legal_person          jsonb,
    created_at            timestamptz NOT NULL DEFAULT now(),
    updated_at            timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT participants_identifier_key UNIQUE (identifier)
);

CREATE TABLE user_participants (
    user_id           uuid NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    participant_id    uuid NOT NULL REFERENCES participants (id) ON DELETE CASCADE,
    local_identifier  text,
    created_at        timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (user_id, participant_id)
);
CREATE INDEX user_participants_participant_idx ON user_participants (participant_id);

CREATE TABLE privacy_notices (
    id              uuid PRIMARY KEY,
    contract_uri    text NOT NULL,
    title           text,
    provider_id     uuid NOT NULL REFERENCES participants (id) ON DELETE RESTRICT,
    consumer_id     uuid REFERENCES participants (id) ON DELETE RESTRICT,
    payload         jsonb NOT NULL,
    archived_at     timestamptz,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX privacy_notices_active_contract_idx
    ON privacy_notices (contract_uri, provider_id)
    WHERE archived_at IS NULL;

CREATE TABLE consents (
    id                  uuid PRIMARY KEY,
    user_id             uuid NOT NULL REFERENCES users (id) ON DELETE RESTRICT,
    privacy_notice_id   uuid NOT NULL REFERENCES privacy_notices (id) ON DELETE RESTRICT,
    provider_id         uuid NOT NULL REFERENCES participants (id) ON DELETE RESTRICT,
    consumer_id         uuid NOT NULL REFERENCES participants (id) ON DELETE RESTRICT,
    parent_consent_id   uuid REFERENCES consents (id) ON DELETE SET NULL,
    status              text NOT NULL,
    consented           boolean NOT NULL,
    contract_uri        text,
    snapshot            jsonb NOT NULL,
    created_at          timestamptz NOT NULL DEFAULT now(),
    updated_at          timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT consents_status_check CHECK (status IN
        ('PENDING','DRAFT','GRANTED','REVOKED','EXPIRED','TERMINATED','REFUSED')),
    CONSTRAINT consents_parent_not_self CHECK (parent_consent_id IS DISTINCT FROM id)
);
CREATE INDEX consents_user_status_idx ON consents (user_id, status);
CREATE INDEX consents_provider_idx ON consents (provider_id);
CREATE INDEX consents_consumer_idx ON consents (consumer_id);
CREATE INDEX consents_privacy_notice_idx ON consents (privacy_notice_id);
CREATE UNIQUE INDEX consents_active_per_notice_idx
    ON consents (user_id, privacy_notice_id)
    WHERE status = 'GRANTED';

CREATE TABLE consent_events (
    id            uuid PRIMARY KEY,
    consent_id    uuid NOT NULL REFERENCES consents (id) ON DELETE CASCADE,
    event_state   text NOT NULL,
    event_type    text NOT NULL DEFAULT 'explicit',
    actor         text,
    occurred_at   timestamptz NOT NULL DEFAULT now(),
    details       jsonb
);
CREATE INDEX consent_events_consent_idx ON consent_events (consent_id, occurred_at);
```

Notes on specific constraints:

- `consents_active_per_notice_idx` makes "at most one granted consent per user per privacy notice"
  a database invariant. The parent/child re-grant chain relies on the old consent being revoked
  before the new one is granted, which this enforces.
- `consent_events` is **append-only**. Nothing updates or deletes a row; it is the audit trail.
- `ON DELETE RESTRICT` on `consents` means a participant with consents cannot be hard-deleted.
  TICKET-005 defines the deregistration semantics that sit on top of this.

### Entity: `User`

| Field | Type | Notes |
|-------|------|-------|
| `id` | `UUID` | Internal primary key |
| `identifier` | `String` | **Globally unique.** Email, DID, URI, or a hash derived from an EUDI Wallet PID. Treated as opaque. |
| `email` | `String` | Optional. Populated from IDP claims. Non-authoritative, used for optional search and notification. **Never a key.** |
| `firstName`, `lastName` | `String` | Optional, display only, refreshed from token claims on each authenticated call |
| `createdAt`, `updatedAt` | `Instant` | |

No password, no OAuth token storage, no JSON-LD self-description, no identifier collection.

### Entity: `Participant`

| Field | Type | Notes |
|-------|------|-------|
| `id` | `UUID` | Internal primary key |
| `identifier` | `String` | **Globally unique** data space participant ID — DID, URI, or IDP-issued string. Taken from the token, never the request body. |
| `legalName` | `String` | Required |
| `selfDescriptionUri` | `String` | Optional, stored as an opaque URI. **Not fetched, not validated, not interpreted.** |
| `email` | `String` | Optional contact address |
| `endpoints` | `jsonb` | Contact and notification endpoints only — see TICKET-020. **No `dataExport`, `dataImport`, `consentExport`, `consentImport`.** |
| `legalPerson` | `jsonb` | Optional registration/address metadata |

No `clientID`, no `clientSecret`, no `dataspaceEndpoint`, no `did` field distinct from `identifier`.

### Entity: `PrivacyNotice`

| Field | Type | Notes |
|-------|------|-------|
| `id` | `UUID` | |
| `contractUri` | `String` | Contract reference |
| `title` | `String` | |
| `providerId`, `consumerId` | `UUID` | FK to `participants` |
| `payload` | `jsonb` | Contract-derived content: purposes, categories of data, recipients, controller details, retention period, PII principal rights, international transfers, withdrawal method. Mapped to a typed record on read. |
| `archivedAt` | `Instant` | `null` while active |

The payload is modelled as a Java record (`PrivacyNoticePayload`) serialised to JSONB. Keeping it as
one column avoids ten near-empty side tables for structures the service only ever reads and returns
whole.

### Entity: `Consent` and `ConsentEvent`

| Field | Type | Notes |
|-------|------|-------|
| `id` | `UUID` | |
| `userId` | `UUID` | FK |
| `privacyNoticeId` | `UUID` | FK |
| `providerId`, `consumerId` | `UUID` | FK |
| `parentConsentId` | `UUID` | The consent this one supersedes. **Single-valued**, resolving original bug 18.2 (schema said `child`, code pushed to `children`). The chain is navigated upward from the newest consent; there is no `child` column to keep in sync. |
| `status` | `ConsentStatus` enum | `PENDING`, `DRAFT`, `GRANTED`, `REVOKED`, `EXPIRED`, `TERMINATED`, `REFUSED` |
| `consented` | `boolean` | Derived from status, persisted for query convenience; a single factory method sets both so they cannot diverge (original bug 18.1) |
| `snapshot` | `jsonb` | Frozen copy of the privacy notice terms at grant time — purposes, data categories, recipients, retention, jurisdiction. A consent must remain readable and auditable even if the privacy notice is later archived. |

`ConsentEvent`: `id`, `consentId`, `eventState`, `eventType`, `actor`, `occurredAt`, `details`.

Event states: `CONSENT_GIVEN`, `CONSENT_REQUESTED`, `CONSENT_REVOKED`, `CONSENT_REFUSED`,
`CONSENT_TERMINATED`, `CONSENT_RE_CONFIRMED`, `CONSENT_RESUMED`, `CONSENT_EXPIRED`.

### Replacing UserIdentifier

The original model had a `UserIdentifier` row per (participant, user-email) pair, plus a federation
algorithm that tried to reconcile them across participants by matching email addresses.

This is replaced by a single rule, implemented in TICKET-004:

> When a participant registers user identifier `X`: if no user with `identifier = X` exists, create
> one and link it to the participant. If one exists, add the participant to its links.
> **Never merge, never match on email, never guess.**

Consequences for this ticket:

- No `user_identifiers` table.
- `consents` has no `providerUserIdentifier` / `consumerUserIdentifier` columns. The consent points
  at one `user_id`; the provider and consumer are participants, and the link table says whether each
  knows that user.
- `user_participants.local_identifier` is a **convenience column only**: a participant may store its
  own internal ID for the user there. It is never used as a lookup key by any other participant and
  never participates in matching.

### Repositories

Micronaut Data JDBC interfaces, one per aggregate:

```java
@JdbcRepository(dialect = Dialect.POSTGRES)
public interface UserRepository extends CrudRepository<User, UUID> {
    Optional<User> findByIdentifier(String identifier);
    Optional<User> findByEmailIgnoreCase(String email);
    boolean existsByIdentifier(String identifier);
}
```

Equivalent repositories for `Participant`, `PrivacyNotice`, `Consent`, `ConsentEvent` and
`UserParticipant`. Paginated queries return `Page<T>` with a **filtered** count — the original
implementation counted the whole collection (original bug 18.3); `Page` derives its total from the
same predicate as the result set, so the bug cannot recur.

## Acceptance Criteria

1. [ ] `V1__initial_schema.sql` applies cleanly to an empty PostgreSQL 16 database via Flyway
2. [ ] All six repositories compile and are injectable
3. [ ] `users.identifier` and `participants.identifier` reject duplicates at the database level
4. [ ] A second `GRANTED` consent for the same (user, privacy notice) is rejected by the partial unique index
5. [ ] `consents.status` rejects any value outside the seven defined states
6. [ ] Archiving a privacy notice frees the `(contract_uri, provider_id)` slot for a new active one
7. [ ] Deleting a user cascades to `user_participants` but is blocked while consents exist
8. [ ] Deleting a participant cascades to `user_participants` but is blocked while consents exist
9. [ ] `ConsentStatus` and `consented` are set together by a single factory method and cannot diverge
10. [ ] `PrivacyNoticePayload` and `ConsentSnapshot` round-trip through JSONB without loss
11. [ ] Repository tests run against a Testcontainers PostgreSQL instance, not a mock
12. [ ] Parameterized tests cover every status value and every invalid status value

## Known Issues Resolved by Design

These were carried as open bugs in the pre-revision plan. The new schema removes them rather than
fixing them:

| Original bug | Why it cannot recur |
|--------------|---------------------|
| 18.2 — parent/child field mismatch (`child` vs `children`) | Single `parent_consent_id` column; no reciprocal field to keep in sync |
| 18.5 — `toReceipt()` references a non-existent field | Receipt generation reads typed record fields, checked at compile time (TICKET-010) |
| 17.9 — no unique index on user email | Uniqueness is on `identifier`, enforced by constraint; email is deliberately non-unique |
| 17.10 — `user` field on UserIdentifier never populated | Entity removed |
| 05-PM-12.3 — `clientSecret` in plaintext | No secrets stored |
| 05-PM-12.7 — `validatePassword` declared but not implemented | No passwords |
| 05-PM-12.6 — no cascade on participant deletion | Every FK declares an explicit `ON DELETE` policy |
| 18.3 — global count instead of filtered count | `Page<T>` derives the count from the query predicate |
